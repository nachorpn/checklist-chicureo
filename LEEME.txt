GESTARK — SINCRONIZACIÓN DE SESIÓN ENTRE SECCIONES · 2026.11.22.12

CAUSA IDENTIFICADA
El módulo Transferencias podía recibir una lectura inicial de Firebase Auth sin usuario
justo después de abrir Gestark. Antes se desuscribía enseguida y mostraba otro login.
También, cada iframe reconfiguraba la persistencia de Firebase al cargarse.

ESTA CORRECCIÓN
- Un módulo dentro de gestark-app.html nunca solicita un segundo login.
- Mantiene activa la observación de Firebase para recibir una sesión restaurada.
- Solo configura browserLocalPersistence cuando alguien inicia sesión de verdad.
- Sigue comprobando autorizado/activo/rol desde Firestore antes de mostrar el módulo.
- Muestra «Reintentar conexión» si la sesión no se propaga; no abre datos sin permiso.
- Conserva navegación rápida de v11, registros, Escáner y listeners de Firestore.

INSTALAR
1. En GitHub, subir SOLO: gestark-auth.js, gestark-app.html, gestark-sw.js.
2. Confirmar cambios (Commit changes).
3. Abrir en Safari: https://nachorpn.github.io/checklist-chicureo/gestark-app.html?actualizar=2026112212
4. Desde iPhone instalado, cerrar Gestark por completo y volver a abrir.
5. Probar Inicio → Transferencias: no debe aparecer un segundo login.

IMPORTANTE
No se modifican reglas de Firebase, credenciales, ni datos de Transferencias.
La verificación inicial requiere conectividad; puede demorarse si Firebase responde lento.
Si una sección indica «Reintentar conexión», utilizar ese botón y reportar el mensaje.
No borrar la PWA antigua hasta comprobar que checklist y registros se conservan.
