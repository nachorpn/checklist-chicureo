GESTARK — CORTE A FIREBASE AUTH ÚNICO — 2026.11.22.5

IMPORTANTE: El ingreso con solo siglas de usuario NO está implementado aún.
Esta versión usa correo y contraseña de Firebase, ya probados con los 5 perfiles.
No subas a GitHub los archivos JSON de importación ni contraseñas.

QUÉ REEMPLAZAR EN LA RAÍZ DE checklist-chicureo:
  1. gestark-auth.js          -> elimina el inicio local y permite solo Firebase
  2. usuarios.js              -> catálogo vacío, sin hashes ni sales
  3. admin.html               -> página segura transitoria (gestión por Firebase Console)
  4. gestark-sw.js            -> renueva caché PWA; expulsa caché antigua al actualizar

NO CAMBIAR: las reglas de Firestore, los datos de Transferencias,
los perfiles authorized_users, la configuración Firebase, ni otros archivos.

PASOS
1. Respalda los cuatro archivos actuales desde GitHub o descarga un ZIP del repositorio.
2. Subelos juntos mediante GitHub > Add file > Upload files > Commit changes.
3. Abre Gestark en ventana privada. Debe pedir CORREO y contraseña Firebase; nunca clave local.
4. Inicia sesión con CIBC y comprueba Transferencias. Comprueba un trabajador en otro equipo.
5. En iPhone, abre la PWA con internet, actualízala y confirma acceso.
6. Si algo falla, restaura los cuatro archivos anteriores desde el respaldo.

LIMITACIONES
- La administración de cuentas desde la propia Gestark requiere un backend protegido;
  por ahora la página de administración enlaza a la consola Firebase.
- Los hashes antiguos siguen en el historial de GitHub; cambia las contraseñas
  por contraseñas fuertes y exclusivas después de la migración.
- Las páginas HTML existentes todavía intentan cargar usuarios.js: por eso lo
  conservamos como archivo vacío, sin credenciales.
- El modo offline no debe otorgar acceso a módulos sensibles si no hay sesión validada.
- Las reglas de Firestore, y NO el ocultamiento visual de GitHub Pages, protegen los datos.
